# 上线前安全检查表

往任何一台云端智能体机器上开这道门之前，逐项过。有一项过不了，先停。

## 授权

- [ ] 这台机器/这个智能体账号是我有权这样改造的（自有实例、或平台条款明确允许）
- [ ] 想清楚了：这道门常驻期间，谁拿到我本地那把私钥，谁就能进这台机器

## 钥匙与账号

- [ ] 登录用户是专用低权账号，不是 root、不是智能体自己的工作账号
- [ ] 密码登录关闭、只认公钥；授权名单里只有本次这一把本地专用钥匙
- [ ] 本地私钥只存本地（如 ~/.ssh，权限 600），从未进过聊天、邮件、代码仓库
- [ ] 主机指纹已在本地首次连接时人工核对（不是无脑 yes）

## 入口

- [ ] 登录服务只听 127.0.0.1；隧道口在落点上也只绑 127.0.0.1（没开 GatewayPorts）
- [ ] 没有新增任何公网可达端口；落点若是公网 VPS，其自身的登录面（22）有钥匙+禁密码保护
- [ ] 端口号是挑过的，没有和落点/智能体侧已有服务撞车

## 常驻与上限

- [ ] 守夜人日志在长，重启次数正常（不是疯狂重连刷日志写满盘）
- [ ] 知道这道门在机器重启/被平台替换后会消失，恢复步骤在 README 里有
- [ ] 登录服务的日志不记录任何密钥内容，只记录时间/来源/成败

## 拆除

- [ ] 智能体侧 `bash agent/stop_all.sh --user` 能一条命令收干净，并实际演练过一次
- [ ] 本地侧知道要删：专用钥匙对 + known_hosts 里对应的那一行
- [ ] 若落点是跳板机，确认没有在这次实验之外留下其他转发或账号
